## Directory Purposes

**`sql_compiler/`:**
- Purpose: Entire runtime library.
- Contains: Python modules only. No templates, static files, or fixtures.
- Key files: `sql_compiler/queryset.py` (main logic), `sql_compiler/compilers/__init__.py` (backend registry).

**`sql_compiler/compilers/`:**
- Purpose: One class per supported Django database ENGINE family.
- Contains: `BaseSQLCompiler` subclasses; `__init__.py` registry.
- Key files: `sql_compiler/compilers/base.py`, `sql_compiler/compilers/postgresql.py`, `sql_compiler/compilers/mysql.py`.

**Repository root:**
- Purpose: Packaging and documentation.
- Contains: `setup.py`, `README.md`, `CLAUDE.md`, `.gitignore`.

**Generated / ignored (not source):**
- `build/`, `dist/`, `django_sql_compiler.egg-info/`: outputs of `python setup.py sdist bdist_wheel`. `dist/` currently holds `django-sql-compiler-0.1.1.tar.gz`, which predates the `setup.py` version of 0.2.3. Do not edit these.
- `.idea/`: JetBrains project settings. Do not edit.

## Key File Locations

**Entry Points:**
- `sql_compiler/__init__.py`: Package import surface used by consumers.
- `sql_compiler/manager.py`: Manager consumers attach to models.

**Configuration:**
- `setup.py`: Version (`0.2.3`), `install_requires=['django']`, classifiers.
- `.gitignore`: Build and IDE artifacts.

**Core Logic:**
- `sql_compiler/queryset.py`: `executable_query` pipeline.
- `sql_compiler/utils.py`: Connection validation and byte decoding.
- `sql_compiler/compilers/__init__.py`: Backend list that drives dispatch and validation.
- `sql_compiler/compilers/postgresql.py`: psycopg2 `mogrify` path.
- `sql_compiler/compilers/mysql.py`: Manual mogrify path.

**Testing:**
- Not present. No test directory or test files. Verification is manual against a live Django project with a supported database (per `CLAUDE.md`).

## Naming Conventions

**Files:**
- Lowercase, single-word module names: `manager.py`, `queryset.py`, `utils.py`, `base.py`, `postgresql.py`, `mysql.py`.
- Package directories are lowercase plural for collections: `compilers/`.
- Documents under `.planning/codebase/` use UPPERCASE.md.

**Directories:**
- Lowercase, no separators: `sql_compiler`, `compilers`.
- Package name uses underscore (`sql_compiler`); distribution name uses hyphen (`django-sql-compiler`), as in `setup.py`.

**Classes:**
- `PascalCase` with a role suffix: `SQLCompilerManager`, `SQLCompilerQuerySet`, `BaseSQLCompiler`, `MySQLCompiler`, `PostgresCompiler`.
- Backend-specific subclasses keep the `Compiler` suffix: `Psycopg2Compiler`, `PostgresTenantsCompiler`.

**Functions and attributes:**
- `snake_case` functions: `validate_connection`, `bytes_to_string`, `compile_sql`, `sql_with_params`.
- Class attribute `backend_name` holds the exact Django ENGINE string (e.g., `'django.db.backends.postgresql'`).

## Where to Add New Code

**New database backend (e.g., another Django ENGINE):**
1. Create a `BaseSQLCompiler` subclass in `sql_compiler/compilers/<driver>.py` (follow `sql_compiler/compilers/postgresql.py` for a cursor-based approach or `sql_compiler/compilers/mysql.py` for a manual approach). Set `backend_name` to the ENGINE string. `compile_sql` must return bytes.
2. Import it in `sql_compiler/compilers/__init__.py`, add it to the `compilers` list, and add it to the `__all__` list. `compiler_map` and `SUPPORTED_BACKENDS` update automatically.
3. Update the "Backend Support" section of `README.md`.
4. Bump `version` in `setup.py` when releasing.

**New Postgres-compatible ENGINE that uses psycopg2 mogrify:**
- Add a subclass of `PostgresCompiler` in `sql_compiler/compilers/postgresql.py` that overrides only `backend_name`. Register it in `sql_compiler/compilers/__init__.py`.

**New public API on the queryset or manager:**
- Primary code: `sql_compiler/queryset.py` (queryset methods/properties) or `sql_compiler/manager.py` (manager behavior).
- Export from `sql_compiler/__init__.py` if consumers should import it directly.

**New helper:**
- Shared helpers: `sql_compiler/utils.py`. Import the compiler registry from `sql_compiler/compilers`, not from the package root, to avoid circular imports.

**Tests (none exist yet):**
- Suggested location: a top-level `tests/` directory (not present). Tests need a configured Django database because compilation goes through a real cursor.
